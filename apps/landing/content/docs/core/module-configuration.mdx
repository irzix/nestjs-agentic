## Overview

`AgenticModule` is configured via two static methods:
1. `forRoot(options)` or `forRootAsync(asyncOptions)`: Registers root providers, default models, execution limits, state stores, and telemetry.
2. `forFeature(options)`: Registers agents, toolsets, and policies in feature modules.

---

## Root Configuration (`forRoot`)

```typescript
import { Module } from '@nestjs/common';
import { AgenticModule } from 'nestjs-agentic';
import { OpenAiModelAdapter } from '@nestjs-agentic/openai';
import { RedisStateStore } from './stores/redis.store';

@Module({
  imports: [
    AgenticModule.forRoot({
      defaultModel: {
        provider: 'openai',
        model: 'gpt-4o',
      },
      modelAdapter: new OpenAiModelAdapter({
        apiKey: process.env.OPENAI_API_KEY,
        maxRetries: 3,
        timeoutMs: 45000,
      }),
      limits: {
        maxTotalTokens: 32000,
        maxIterations: 6,
        timeoutMs: 60000,
      },
      stateStore: new RedisStateStore({
        host: process.env.REDIS_HOST,
        port: 6379,
      }),
    }),
  ],
})
export class AppModule {}
```

## Asynchronous Configuration (`forRootAsync`)

When your model configuration or state store depends on `ConfigService`:

```typescript
@Module({
  imports: [
    AgenticModule.forRootAsync({
      imports: [ConfigModule],
      inject: [ConfigService],
      useFactory: (config: ConfigService) => ({
        defaultModel: {
          provider: 'openai',
          model: config.get('AGENT_MODEL', 'gpt-4o'),
        },
        modelAdapter: new OpenAiModelAdapter({
          apiKey: config.getOrThrow('OPENAI_API_KEY'),
          baseURL: config.get('OPENAI_BASE_URL'),
        }),
        limits: {
          maxTotalTokens: 16000,
          maxIterations: 4,
          timeoutMs: 45000,
        },
      }),
    }),
  ],
})
export class AppModule {}
```

## Feature Registration (`forFeature`)

Feature modules register their own domain agents, toolsets, and policies:

```typescript
@Module({
  imports: [
    AgenticModule.forFeature({
      agents: [FinanceAgent, ComplianceAgent],
      toolSets: [PaymentTools, LedgerTools],
      policies: [HighValueApprovalPolicy, TenantIsolationPolicy],
    }),
  ],
  providers: [PaymentService, LedgerService],
})
export class FinanceModule {}
```

## Deny-by-Default Governance (`defaultPolicies`)

Without `defaultPolicies`, policies are entirely opt-in per tool via `@UsePolicies(...)` — a tool with no annotation ships completely unguarded. `defaultPolicies` runs a shared policy chain against every discovered tool automatically:

```typescript
AgenticModule.forRoot({
  defaultModel: { provider: 'openai', model: 'gpt-4o' },
  defaultPolicies: [SecretRedactionPolicy, RateLimitPolicy],
});

AgenticModule.forFeature({
  toolSets: [PaymentTools],
  // Classes listed in defaultPolicies must also be registered here (or in
  // another forFeature call) so they resolve through DI like any other policy.
  policies: [SecretRedactionPolicy, RateLimitPolicy, HighValueApprovalPolicy],
});
```

Evaluation order is deterministic — module defaults run first, so a deny-by-default guard short-circuits before any tool-specific policy runs:

```
defaultPolicies -> class-level @UsePolicies -> method-level @UsePolicies
```

Opt a tool or an entire toolset class out with `@ExemptFromDefaultPolicies()` — the exemption is discoverable metadata, not a silent bypass, and `@UsePolicies` on the same tool/class still applies:

```typescript
@Tool({ description: 'Read-only lookup' })
@ExemptFromDefaultPolicies()
async getOrderStatus(@Param('orderId') orderId: string) {}
```

With no `defaultPolicies` configured, every existing tool behaves exactly as before.
