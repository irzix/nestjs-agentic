## ScratchpadMemory Store

Complex multi-step agents require a dedicated working memory to track intermediate hypotheses, extracted entities, and incomplete sub-tasks across tool calls without polluting the conversation history.

`ScratchpadMemory` keys entries by `metadata.taskId` (falling back to the record id) within a session, and implements the standard `AgentMemoryStore` interface — there's no separate `get`/`set` key-value API:

```typescript
import { ScratchpadMemory } from '@nestjs-agentic/memory';

const scratchpad = new ScratchpadMemory();

// Save structured task state during turn execution
await scratchpad.save({
  id: 'analyzedFiles',
  sessionId: 'session_42',
  type: 'scratchpad',
  content: JSON.stringify(['src/app.ts', 'src/auth.ts']),
  metadata: { taskId: 'analyzedFiles' },
  timestamp: new Date(),
});

// Read the full working set for a session
const workingSet = await scratchpad.getWorkingSet('session_42');

// Or search within it
const matches = await scratchpad.recall('auth.ts', { sessionId: 'session_42' });
```

There is no built-in `toSystemPrompt()` formatter today — formatting `getWorkingSet()`'s results into a system-prompt section is left to the application.
