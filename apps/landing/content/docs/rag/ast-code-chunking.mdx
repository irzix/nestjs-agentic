## Why AST-Aligned Chunking?

Splitting code by line or token count cuts across functions, leaving the model with broken syntax and missing parameter context.

`AstCodebaseSplitter` parses source files along syntactic boundaries and extracts semantically coherent chunks. It's deliberately regex-based rather than a full TypeScript compiler AST parse — this avoids a `ts-morph`/TypeScript-program dependency and is immune to catastrophic regex backtracking (ReDoS) by construction:

- **Class Declarations**: Preserves class decorators, properties, constructor signatures, and (optionally) sub-splits large classes into per-method chunks.
- **Functions, Interfaces, Type Aliases, Enums**: Each preserved as a self-contained chunk with JSDoc and import metadata.
- **Import Tracking**: Module specifiers are extracted into chunk metadata for downstream dependency-graph strategies.

```typescript
import { AstCodebaseSplitter } from '@nestjs-agentic/rag';

const splitter = new AstCodebaseSplitter({ splitClassMethods: true });

const chunks = await splitter.splitDocument({
  id: 'payment-service',
  title: 'src/payment.service.ts',
  rawContent: fileContent,
  chunks: [],
  metadata: {},
  timestamp: new Date(),
});

for (const chunk of chunks) {
  console.log(chunk.metadata?.symbolName, chunk.metadata?.kind);
  console.log(chunk.content);
}
```
