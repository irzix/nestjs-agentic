## Hybrid Retrieval Architecture

Pure vector search struggles with exact identifier names (e.g. `UserRepository.findByTenantId`), while pure lexical matching misses conceptual synonyms.

`HybridVectorStore` supports two ways of combining the dense and sparse rankings, via `fusionMethod`:

- `'weighted'` (default) — max-normalized weighted sum:

```text
score(d) = (1 - vectorWeight) * normalize(bm25Score(d)) + vectorWeight * normalize(cosineScore(d))
```

- `'rrf'` — Reciprocal Rank Fusion, combining each ranker's *rank position* instead of its raw score, so dense and sparse scores never need to be normalized onto a common scale:

```text
RRF_score(d) = sum over each ranker m ranking d: weight_m / (k + rank_m(d))
```

The sparse score is real BM25 (Robertson/Sparck-Jones), computed from corpus-level statistics maintained incrementally as chunks are added or removed:

```text
bm25(D, Q) = sum over query terms t: IDF(t) * (f(t,D) * (k1 + 1)) / (f(t,D) + k1 * (1 - b + b * |D| / avgdl))
```

`k1` (term-frequency saturation, default `1.2`) and `b` (document-length normalization, default `0.75`) are configurable.

```typescript
import { HybridVectorStore } from '@nestjs-agentic/rag';

const store = new HybridVectorStore({
  embeddingProvider: myEmbeddingProvider,
  vectorWeight: 0.5, // sparse weight is derived as 1 - vectorWeight
  bm25K1: 1.2,
  bm25B: 0.75,
  fusionMethod: 'rrf', // or 'weighted' (default)
  rrfK: 60,
});

await store.addChunks([
  {
    id: 'chunk_1',
    content: 'export class AuthService { validateToken() {} }',
    metadata: { filePath: 'src/auth.service.ts' },
  },
]);

const results = await store.searchHybrid('How does token validation work?', 5);
```

`reciprocalRankFusion` is also exported standalone, for fusing any ranked id lists (e.g. RAG-Fusion-style multi-query variants) outside of `HybridVectorStore`:

```typescript
import { reciprocalRankFusion } from '@nestjs-agentic/rag';

const fused = reciprocalRankFusion(
  [
    ['doc_a', 'doc_b'], // ranker 1's results, best first
    ['doc_b', 'doc_c'], // ranker 2's results, best first
  ],
  { k: 60 },
);
```

## Batched Embedding & Caching

`addChunks` embeds any chunk missing a vector via batched `embedDocuments` calls (`embeddingBatchSize`, default `100`), rather than one `embedQuery` call per chunk — ingesting hundreds of chunks issues a handful of requests instead of hundreds of individual ones.

`CachedEmbeddingProvider` wraps any `EmbeddingProvider` with a cache keyed by a hash of the text (and a `cacheNamespace`, to keep distinct models/dimensions from colliding), so re-ingesting unchanged content or repeating an identical query skips the network call entirely:

```typescript
import { CachedEmbeddingProvider, OpenAIEmbeddingAdapter, HybridVectorStore } from '@nestjs-agentic/rag';

const cachedEmbedder = new CachedEmbeddingProvider({
  provider: new OpenAIEmbeddingAdapter({ apiKey: process.env.OPENAI_API_KEY }),
  cacheNamespace: 'text-embedding-3-small', // distinguishes this model/dimension from others sharing a store
  maxSize: 5000, // in-memory LRU cache size, ignored when `store` is provided
});

const store = new HybridVectorStore({ embeddingProvider: cachedEmbedder });
```

By default, the cache is an in-memory LRU. Pass a `StateStore` (e.g. `RedisStateStore` from `@nestjs-agentic/core`) to share the cache across processes:

```typescript
const cachedEmbedder = new CachedEmbeddingProvider({
  provider: new OpenAIEmbeddingAdapter({ apiKey: process.env.OPENAI_API_KEY }),
  store: myRedisStateStore,
  cacheNamespace: 'text-embedding-3-small',
  ttlSeconds: 60 * 60 * 24, // only applies to store-backed caches
});
```
