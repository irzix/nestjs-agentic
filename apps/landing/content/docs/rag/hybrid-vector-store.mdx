## Hybrid Retrieval Architecture

Pure vector search struggles with exact identifier names (e.g. `UserRepository.findByTenantId`), while pure lexical matching misses conceptual synonyms.

`HybridVectorStore` blends both scores with a max-normalized weighted sum:

```text
score(d) = (1 - vectorWeight) * normalize(termScore(d)) + vectorWeight * normalize(cosineScore(d))
```

The sparse `termScore` today is term-frequency based (matches divided by document length), not full BM25 with IDF weighting — see [issue #131](https://github.com/irzix/nestjs-agentic/issues/131) for tracked work to add real IDF/k1/b saturation. Reciprocal Rank Fusion is tracked separately in [issue #130](https://github.com/irzix/nestjs-agentic/issues/130) and is not yet implemented.

```typescript
import { HybridVectorStore } from '@nestjs-agentic/rag';

const store = new HybridVectorStore({
  embeddingProvider: myEmbeddingProvider,
  vectorWeight: 0.5, // sparse weight is derived as 1 - vectorWeight
});

await store.addChunks([
  {
    id: 'chunk_1',
    content: 'export class AuthService { validateToken() {} }',
    metadata: { filePath: 'src/auth.service.ts' },
  },
]);

const results = await store.searchHybrid('How does token validation work?', 5);
```
